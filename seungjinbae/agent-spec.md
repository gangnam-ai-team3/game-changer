# 개인 에이전트 명세서 — 승진배 / 근거 감사 및 검증 판정 에이전트

## 담당자: 승진배

## 이 에이전트가 하는 일

- 레드팀 검토(정아현)가 넘긴 리스크 서술과 검증·개선 항목을, 담당자·기한·근거 존재·구조 유사성·표본 신뢰도 기준으로만 항목별 통과/반려 판정하고, 조립(유주심)에 넘길 ValidatedDecision(판정 표 + 총평)을 만든다

## 입력 (무엇을 받나 — 앞 단계에서 넘어오는 것)

- 리스크 서술 — 이번 업데이트의 핵심 리스크 3~6문장 (어떤 변경이 어떤 플레이어 모델에게 어떤 마찰을 일으키는지)
- 검증·개선 항목 목록: 항목명 / 담당자 / 기한 / 근거 ID (레드팀 검토가 만든 RiskAssessment에서 옴)
- (판정에 필요하지만 아직 자동으로 연결돼 있지 않은 것) 근거 ID가 실제로 존재하는지 대조할, 앞 단계(hy 수집·res 근거 구조화)의 원본 데이터

## 출력 (무엇을 내놓나 — 다음 단계로 넘기는 형식)

- 항목별 판정 표: `# | 항목 | 담당자 | 기한 | 판정 | 사유 (한 줄)` — 판정 값은 통과/반려 둘 중 하나만
- 표 아래 총평 한 줄 — 건수 요약(N건 중 M건 통과) + 출시 권고(Hold / Revise / Go)
- 결과 파일: `verify/validated-decision(-실행ID).md`. 기존 파일은 지우지 않고 있으면 -2, -3으로 쌓음
- 표와 총평 외의 설명·제안·수정안은 내놓지 않음 (대안 제시는 이 칸의 역할이 아님)

## 쓰는 도구 (스킬 / MCP / 파일 등)

- `.claude/agents/validated-decision.md` — Claude Code 서브에이전트 정의. 도구는 Read, Write만 사용
- `seungjinbae/` 폴더 — readme.md(역할·처리 절차), input-sample.md·stub.md(입력 형식과 빈 템플릿), result.md(출력 형식과 예시), screen.html(입력 폼과 판정 로직을 그대로 재현한 미리보기 화면)
- `verify/` 폴더 — 실행 결과를 쌓는 자리. screen.html은 판정 결과를 표 모양 그대로 보여주는 연습용 화면

## 핵심 지시 (이 에이전트에게 시키는 말의 요지)

- 담당자가 비어 있거나 "미정"·"TBD"면 반려, 기한이 없거나 yyyy/mm/dd 형식이 아니면 반려 — 다른 판단보다 먼저 확인한다
- 근거 ID가 앞 단계 수집 결과에 실제로 있는지, 과거 VOC 불만 원인과 이번 기획의 이용 조건이 진짜 같은 구조인지 확인하고, 근거 15건 미만이거나 언어권 3개 미만이면 반려한다
- 판정 값은 통과/반려 두 가지만 쓰고 "보류"·"부분 통과" 같은 중간값은 쓰지 않으며, 통과 항목에도 왜 통과인지 사유를 남긴다
- 좋은 개선안인지, 더 나은 대안이 있는지는 판단하지 않는다 — 근거를 감사하는 사람이지 기획을 다시 쓰는 사람이 아니다

## 막힌 점 ← 솔직하게

- "근거 존재 확인"과 "유사 구조 검증" 단계가 실제로는 앞 단계(hy/res)의 원본 수집 데이터를 자동으로 조회하지 못한다. 실제 실행 때도 "앞 단계 수집 결과가 제공되지 않았다"는 조건을 프롬프트로 직접 알려줘야 판정이 됐다 — 자동 연동 방법이 아직 없음
- 출시 권고(Hold/Revise/Go)는 통과 항목의 "리스크 등급(Critical/High 등)"을 기준으로 나누는데, 정작 "받는 것" 입력 필드에는 리스크 등급이 정의돼 있지 않다. 실제 실행에서는 리스크 서술 문장에서 등급을 그때그때 추론했다 — 등급을 어디서, 누가 매길지 아직 정하지 않음
- 표본 기준(근거 15건, 언어권 3개)이 왜 이 숫자인지 근거가 없다. res(유주심) 쪽 기준(언어권 일반 표본 100건, 관련 근거 15건)과 겹치는 부분(근거 15건)과 다른 부분(언어권 판단 방식)이 있는데, 둘이 서로 맞물리는지 아직 맞춰보지 않았다
- `verify/` 폴더에 실행마다 새 파일(-2, -3…)이 쌓이기만 해서, 가장 최신 판정이 무엇인지 파일 이름만으로는 알기 어렵다 — 이력 정리 방법이 아직 없음
- `seungjinbae/screen.html`과 `verify/screen.html`은 둘 다 정적 데모라 실제 `verify/` 실행 결과와 자동으로 연결돼 있지 않다. 최신 결과를 화면에 반영하려면 사람이 직접 내용을 옮겨 붙여야 한다
