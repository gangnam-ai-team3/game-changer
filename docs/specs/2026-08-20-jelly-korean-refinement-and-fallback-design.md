# Jelly 한국어 편집과 안전 대체 경로 설계

## 목적

최신 업데이트 점검에서 정아현 위험 점검 에이전트(Jelly)는 `claude-sonnet-5`로 정상 응답했지만, 응답 문장의 가운뎃점이 Res의 한국어 문장 검사에서 거부됐습니다. 이 결과가 실제 API 장애와 같은 `SOURCE_UNAVAILABLE`로 처리되었고, 이후 에이전트 실행이 중단되며 최종 판정도 `Hold`로 바뀌었습니다.

이 설계의 목적은 다음 두 가지입니다.

1. Res의 한국어 규칙을 문장 차단이 아닌 문장 편집에 사용합니다.
2. 정상적인 핵심 분석을 선택형 자연어 보강 실패 때문에 버리지 않습니다.

## 승인된 원칙

- Jelly와 Res의 관계는 자연어 생성과 편집의 관계로 정의합니다.
- Res는 Jelly가 만든 문장의 의미를 바꾸지 않고 한국 실무자가 읽기 자연스러운 표현으로 다듬습니다.
- 표기, 어미, 번역투, 반복 같은 문체 문제는 실패 사유가 아닙니다.
- 근거 ID, 행 번호, 허용된 분류값, 위험 등급, 최종 판정과 같은 의미 계약은 계속 엄격하게 검증합니다.
- 핵심 분석이 완료된 경우, Jelly 보강 실패만으로 `analysis_incomplete`를 설정하지 않습니다.
- 실제 자료 수집 실패, 정규화된 근거 부족, 표본 기준 미달 때만 분석 미완료로 판정합니다.

## 처리 흐름

1. 정책 코드가 근거에서 위험 목록과 등급을 먼저 확정합니다.
2. Jelly는 최대 8개 위험에 연결된 비식별 요약만 받아 동향, 원인, 개선 방향을 작성합니다.
3. Res는 Jelly 응답을 다음 순서로 처리합니다.
   - 행 번호와 행 수가 입력과 정확히 일치하는지 확인합니다.
   - 동향이 `긍정`, `중립`, `부정`, `위험` 중 하나인지 확인합니다.
   - 가운뎃점은 쉼표나 자연스러운 연결 표현으로 바꾸고, 불필요한 공백과 문장부호를 정리합니다.
   - 빈 원인과 개선 방향은 코드가 이미 검증한 위험 설명과 확인 질문으로 보완합니다.
   - 다듬은 문장을 한국어 비즈니스 글쓰기 기준으로 확인합니다.
4. Jelly의 동향 집계는 실행 과정과 상세 보기에 사용하지만, 정책 코드가 확정한 위험 등급과 판정을 덮어쓰지 않습니다.
5. Jelly가 실패하면 코드가 만든 위험 점검 결과를 유지하고, 실행 상태에 `대체 경로 사용`을 남긴 뒤 승진배 근거 검증 에이전트를 계속 실행합니다.

## 오류 구분

### 편집 대상

- 가운뎃점, 과도한 특수문자
- 반복되는 어미와 서술어
- 번역투와 어색한 호응
- 불필요한 공백과 문장부호
- 코드가 안전하게 보완할 수 있는 빈 원인 또는 빈 개선 방향

### 계약 실패

- 행 누락, 중복, 알 수 없는 행 번호
- 허용되지 않은 동향값
- 근거 ID 범위 이탈
- 응답 구조 훼손
- 비식별 경계 위반

### 외부 호출 실패

- 인증 실패
- API 응답 불가
- 시간 초과
- 응답 본문 누락

문장 형식 문제는 계약 실패나 외부 호출 실패로 바꾸지 않습니다. 로그와 화면에는 비밀 정보나 모델 원문 대신 코드가 정한 안전한 상태만 남깁니다.

## 판정 정책

다음 경우만 `analysis_incomplete=True`로 처리합니다.

- 수집 단계가 실패했습니다.
- 정규화된 근거가 없습니다.
- 필수 표본 기준을 충족하지 못했습니다.
- 근거 ID와 위험의 연결을 코드로 검증할 수 없습니다.

Jelly, 페르소나 문구 보강, 승진배 근거 판정기 같은 부가 설명 단계가 실패해도 코드 정책이 핵심 분석을 완료했다면 최종 판정을 바꾸지 않습니다. 대신 `fallback_used=True`와 해당 에이전트의 대체 경로 상태를 기록합니다.

## 검증 기준

1. Jelly가 가운뎃점을 포함한 응답을 반환해도 자연스러운 쉼표 표현으로 수정하고 정상 완료합니다.
2. Jelly가 빈 원인이나 빈 개선 방향을 반환하면 기존 위험 정보로 보완합니다.
3. 잘못된 행 번호나 허용되지 않은 동향은 계약 실패로 거부합니다.
4. 완전한 코퍼스 분석에서 Jelly가 실패해도 `analysis_incomplete=False`를 유지하고 승진배 에이전트를 계속 실행합니다.
5. 수집 실패, 빈 근거, 표본 미달은 기존처럼 `Hold`를 유지합니다.
6. 판정, 위험 ID, 등급, 근거 ID, 신뢰도는 Jelly 문장 편집 전후에 동일합니다.
7. API 키, 원문, 공급자의 상세 오류 메시지는 이벤트, JSONL, 최종 결과에 남지 않습니다.

## 구현 범위

- Jelly 입력 프롬프트와 응답 편집 규칙
- Jelly 오류 분류
- 업데이트 오케스트레이터의 대체 경로 정책
- 공유 호출 예산을 사용하는 Jelly 다음 단계 실행
- 관련 단위 테스트와 통합 테스트
