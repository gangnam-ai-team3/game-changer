# GAME-CHANGER 디자인 스펙

출시 전 게임 업데이트의 예상 반응/검증 조건을 점검하는 1페이지 웹앱.
톤: **토스(Toss) 스타일** — 밝은 배경, 절제된 컬러, 부드러운 카드 그림자, 하나의 확실한 블루 액센트.

---

## 1. 디자인 토큰

### 컬러
| 이름 | 값 | 용도 |
|---|---|---|
| 배경 | `#F7F8FA` | 페이지 전체 배경 |
| 카드 | `#FFFFFF` | 모든 카드 배경 |
| 텍스트(진함) | `#191F28` | 제목, 본문 강조 |
| 텍스트(보통) | `#6B7684` | 본문, 설명 |
| 텍스트(연함) | `#8B95A1` | 캡션, 라벨 |
| 보더 | `#E5E8EB` | 카드 테두리, 구분선 |
| 블루(메인) | `#3182F6` | 브랜드/포인트 컬러, "긍정" 의미 |
| 블루(연함) | `#EBF2FE` | 아이콘 배경, 칩 비활성 배경 |
| 레드(위험) | `#FF5B4C` | "부정/위험" 의미 전용 |
| 레드(연함) | `#FFEEEC` | 위험 카드 배지 배경 |
| 앰버 | `#FF9F1C` | 중간 경고 수치 |
| 회색(중립) | `#C7CDD6` / `#B7BEC9` | "기타/중립" 의미, 지도 기본 점 |

**컬러 원칙**: 의미 없는 다색 사용 금지. 색은 항상 "부정=빨강 / 긍정=블루 / 중립=회색" 3색 체계만 사용한다. 캐릭터 일러스트(아바타)만 예외적으로 화려한 색을 써도 된다 — 페이지에서 유일하게 "과감해도 되는" 요소.

### 타이포그래피
- 폰트: Pretendard 1종 (한글 산세리프), 굵기로 위계 구분 (800 / 700 / 600 / 400)
- 브랜드 워드마크: 대문자, 초대형(56–64px), 800 weight
- 소제목: 16px 내외, 하나의 크기·색으로 통일 (일부만 굵게/진하게 하지 않음)
- 섹션 타이틀: 16–20px, 800 weight + 왼쪽에 블루 아이콘 배지(26x26, `#EBF2FE` 배경 + 블루 아이콘) 세트로 사용
- 금지: ALL CAPS 라벨, 문장 중 한 단어만 강조, 불필요한 eyebrow 라벨

### 레이아웃/형태
- 카드 radius: 14–20px
- 카드 그림자: `0 1px 2px rgba(15,23,42,.04), 0 8px 20px rgba(15,23,42,.05)` (테두리만 있는 밋밋한 카드 금지)
- 버튼(칩): pill 형태, height 36–38px
- 전체 폭: max-width 920px, 좌측 정렬 콘텐츠(중앙 정렬 X)
- 큰 흐름 구분은 **가운데를 가로지르는 세로선/파이프라인 형태 금지**. 대신 좌측 정렬 "1. 2." 번호 + 구간 사이 `border-top` 구분선(section-divider) 사용

## 2. 페이지 구조 (섹션 순서)

### Hero
- 초대형 워드마크: `GAME-CHANGER` (대문자, "changer" 부분만 블루)
- 바로 아래, 크기·색이 통일된 한 줄(줄바꿈 시 자연스럽게 2~3줄로 balance) 소개 문구
- 워드마크와 소개 문구 사이 간격은 좁게(12px 내외) — 서로 떨어져 보이면 안 됨

### Step 1. 업데이트 정보 입력
입력 카드는 **입력 가능한 실제 폼 필드**로 구성한다 (텍스트만 나열된 목업 금지).
카드마다: 좌상단에 파란 아이콘(26x26, blue-soft 배경) + 작은 굵은 타이틀.

1. **업데이트 기본 정보** 카드
   - 최상단: "무기 밸런스 / UI·UX / 시스템" 중 하나를 고르는 단일 선택 pill 버튼 그룹
   - 이어서 텍스트 입력 필드: 게임명, 업데이트 이름, 현 상태, 변경 내용, 목표, 타겟 (2열 배치)
2. **반영 세부 조건** 카드
   - 텍스트 입력: 예상 효과, 우려, 기타 상세 내용
3. **자료 출처** 카드
   - 다중 선택 가능한 토글 칩: Steam 커뮤니티 / X / 공식 카페 / 공식 CSV 연동 / 디스코드

### Step 2. 점검 시작
- 중앙(또는 좌측) 정렬 단일 CTA 버튼 "업데이트 점검 시작"
- **색상은 블루가 아닌 다크 네이비/잉크(`#191F28`)** — 페이지에 블루가 이미 많이 쓰이므로 CTA만 구분되는 색으로
- 클릭 시: 짙은 배경의 로딩 pill(점 3개 pulse 애니메이션, "기존 VOC와 유사 사례 매칭 중") 약 1.5~2초 노출 → 이후 결과 섹션이 등장
- **결과는 버튼을 누르기 전까지 화면에 전혀 보이지 않아야 한다** (점진적 공개)

### Step 3. 점검 결과
섹션 제목은 모두 "블루 아이콘 + 굵은 타이틀" 형식으로 통일. 아래 소섹션 사이에는 구분선(`section-divider`, `border-top:1px solid`)을 넣어 시각적으로 끊어준다 — 특히:
- "출시 전 반응 반영 예상" ↔ "유저 유형별 반응" 사이
- "언어·지역별 반응" ↔ "근거와 검증 지표" 사이
- "근거와 검증 지표" ↔ "출시 후 검증할 지표" 사이

#### 3-1. 요약 (검증 결과)
- 위험/보류 등급을 나타내는 verdict 카드: 흰 배경 + **왼쪽 컬러 강조선**(예: 빨강) + 작은 pill 배지 + 제목 + 한 줄 설명 (그라데이션 배경 등 장식 효과 금지)
- 3개의 원형(도넛) 게이지: 퍼센트 숫자를 중앙에 두고 링 색으로 심각도 표현 (빨강/앰버/블루)

#### 3-2. 출시 전 반응 반영 예상
- 2x2 카드 그리드, 색 테두리 없는 플랫한 흰 카드
- 카드 구성: 작은 컬러 점(dot) + 짧은 헤드라인 + 1~2문장 설명 + 출처 태그

#### 3-3. 유저 유형별 반응 (페르소나)
- 카드형, 클릭하면 아코디언으로 펼쳐짐 (전체 카드가 클릭 영역)
- **카드 안 정보 위계**: 1) 유저 유형명(가장 크고 진하게, 최우선) 2) 공감 비율 %(그다음으로 크고 색상 강조) 3) "공감한 비율" 같은 캡션은 가장 작고 옅게
- 3D 스타일 캐릭터 아바타: 그라데이션 음영 + 하이라이트 + drop-shadow로 입체감, 유형별로 헤어스타일/색/소품이 다르게, 컬러 그라데이션 사각 배경 안에 배치
- "유사 사례 평균 vs 이번 예측" 2줄 비교 막대
- 예시 반응 인용문
- **펼치기 버튼은 텍스트 라벨 없이 화살표 아이콘 하나만** — 누르면 세부 반응 사유(항목별 %)와 추가 인용문이 아코디언으로 열리고, 다시 누르면 접힘

#### 3-4. 언어·지역별 반응
- 화면이 넓을 때: **좌측 = 실제 대륙 형태를 알아볼 수 있는 점지도(dot map)**, 우측 = 리스트
  - 지도 점은 회색 단색, 그 위에 언어권별 원형 마커(부정 비율이 높을수록 진한 빨강, 낮으면 회색)
  - 마커 클릭 시 우측 리스트의 해당 언어권 항목이 자동으로 펼쳐짐(스크롤 포함)
- 우측 리스트: 국기 배지(블루톤 통일, 무지개색 금지) + 언어명 + 부정/긍정 2색 분할 막대(빨강/블루, 나머지는 회색) + "부정 N% · 긍정 N%" 텍스트 — **전부 한 줄에** 배치
- 리스트는 **기본 4개만 노출**, 나머지는 접혀 있다가 "더보기 · N개 언어권 더 보기" 버튼으로 펼침(다시 누르면 "접기")
- 지도에는 리스트에 없는(접혀 있는) 언어권 마커도 항상 표시되어야 하며, 클릭하면 리스트 쪽이 자동으로 펼쳐짐

#### 3-5. 근거와 검증 지표
- 선형 그래프(SVG): 두 시리즈(유사 사례 평균 / 이번 업데이트 예측) 비교, y축 퍼센트 라벨, x축은 출시일 기준 D-14~D+30, 범례 + 한 줄 설명 문구 필수(그래프가 무엇을 뜻하는지 바로 알 수 있게)
- 근거 원문: 총 건수 표시("총 N건 · 관련도 높은 순") + 출처 필터 칩 + 고정 높이 내부 스크롤 리스트(하단 페이드 효과) + "N건 더 보기" 버튼

#### 3-6. 출시 후 검증할 지표
- 단순 3열 표: 지표 / 목표치 / 측정 방법

#### 하단: PDF 저장
- 우측 정렬, CTA와 동일한 다크 네이비 톤이지만 더 작은 버튼: "⬇ PDF로 저장하기"
- 클릭 시 모달: 섹션별 체크박스로 포함 항목 선택 후 내보내기

## 3. 인터랙션 원칙

- 결과는 행동(버튼 클릭) 전까지 절대 미리 보이지 않는다
- 펼치기/접기는 아이콘(화살표)만으로 암시, 텍스트 설명 문구("눌러서 보세요" 등)를 달지 않는다
- 모션은 최소한으로: 로딩 pulse 1개, 아코디언 height 트랜지션 정도만. 카드마다 스크롤 등장 애니메이션 금지
- 지도 마커 ↔ 리스트 항목은 서로 연동(클릭 시 상대 UI가 반응)

## 4. 하지 말아야 할 것 (금지 목록)

- 카드 배경에 그라데이션 워시 장식
- 의미 없는 무지개색(국기 배지 등에 파랑/검정/주황/빨강/초록 무작위 사용)
- 페이지 가운데를 관통하는 세로 타임라인/파이프라인 라인
- "인풋/아웃풋" 같은 개발 용어를 사용자 대상 라벨로 노출
- "세부내역 1", "세부내역 2" 같은 무의미한 번호 라벨 — 항상 내용에 맞는 실제 제목 사용
- ALL CAPS eyebrow 라벨, 문장 속 한 단어만 강조하는 타이포 장식

## 5. 기술 구현 메모

- 단일 HTML 파일로 완결(인라인 CSS/JS/SVG), 외부 의존은 폰트(Pretendard CDN)와 PDF 내보내기(html2pdf.js CDN) 2가지뿐 — 오프라인에서도 나머지 기능은 정상 동작해야 함
- 세계지도는 임의의 타원이 아니라 실제 지리 데이터(예: Natural Earth 저해상도 데이터)를 점(dot) 좌표로 변환해 사용 — 위경도 범위에 맞춰 투영식을 계산해 캔버스 안에 불필요한 여백이 남지 않도록 함
- 아바타/아이콘은 인라인 SVG(그라데이션 fill + drop-shadow)로 제작, 외부 이미지에 의존하지 않음
