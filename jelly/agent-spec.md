# 개인 에이전트 명세서 — jelly

담당자: 정아현

## 이 에이전트가 하는 일

- res 에이전트가 검증한 근거 ID를 콘텐츠·이슈 단위로 모아, 동향(긍정/부정/중립/위험)과 원인·개선 방향을 구조화한다

## 입력 (무엇을 받나 — 앞 단계에서 넘어오는 것)

- 콘텐츠 / 이슈 / 근거 ID / 언어 / 출처 (직접 입력하거나 res 폴더에서 불러온 값)
- 근거 ID가 가리키는 res의 실제 리뷰 내용 (res 에이전트의 출력)

## 출력 (무엇을 내놓나 — 다음 단계로 넘기는 형식)

- 콘텐츠·이슈별 동향 표(동향 / 근거 내용 / 원인 / 언어 / 출처 / 신뢰도)
- 동향 그래프 — 전체 원 그래프 + 언어별 막대 그래프
- 콘텐츠 별 동향 분석 — 이슈마다 원인 / 근거 / 개선을 구분해 서술
- 종합 — 전체 동향 요약 뒤에 개선 방향을 우선순위 순서로 2~4개 항목으로 나눠 제시하고, 위험 신호는 특정 언어에서만 있는지 근거 언어 전체에 공통인지 나눠서 설명

## 쓰는 도구 (스킬 / MCP / 파일 등)

- `jelly/stub.md` (모양 견본), `jelly/input.md` (동향 입력 표)
- `.claude/agents/jelly.md` — Claude Code 서브에이전트 정의. res 폴더를 읽기 전용으로 조회해 `jelly/result.md`를 씀
- `jelly/call-agent.js` — 같은 역할 지시문(`jelly.md`)으로 실제 Claude API(claude-opus-5)를 직접 호출하는 로컬 서버. `jelly/index.html`의 표 입력을 받아 구조화된 JSON으로 분석 결과를 돌려주고, 화면에 바로 그려서 보여줌 (파일에는 쓰지 않음). 열쇠(API 키)는 팀 폴더 맨 위 `.env`에서만 읽고 화면 쪽에는 두지 않음

## 핵심 지시 (이 에이전트에게 시키는 말의 요지)

- 근거 내용이 없으면 "근거 부족"으로 비워 두고 지어내지 않는다
- 법적 이슈나 대규모 이탈로 이어질 수 있는 표현은 다른 신호보다 우선해 '위험'으로 분류한다
- 콘텐츠·이슈가 같으면 묶어서 보여주고, 종합은 원인을 그대로 나열하지 않고 우선순위를 매겨 서술한다

## 막힌 점 ← 솔직하게

- `jelly/call-agent.js`로 실제 API를 쓰다 보니 워크스페이스 사용량 한도에 걸린 적이 있음(실제로 한 번 겪음) → 한도를 누가 관리하고, 걸렸을 때 팀이 어떻게 알아채고 대응할지 아직 안 정함
- 결과가 `jelly/result.md`(서브에이전트로 실행할 때)나 화면(`index.html`로 실행할 때) 중 한쪽에만 남고 서로 연결되지 않아서, 두 경로 어느 쪽으로 실행하든 이전 실행 결과와 비교하거나 누적 추이를 보려면 별도 저장 방법이 필요함 → 아직 정하지 않음
